You can use the official Prefect Docker image to run a server in a container.

If you're running a server in a Docker container, you need to:

- Port forward the server to your local machine (e.g. `-p 4200:4200`)
- Set the `--host` flag on the `prefect server start` command to `0.0.0.0`
- Set the API server address, `PREFECT_API_URL`, to use Prefect within a container.

For example:

```bash
docker run -p 4200:4200 -d --rm prefecthq/prefect:3-latest -- prefect server start --host 0.0.0.0
```

<Tip>
The `-d` flag runs the container in detached mode (i.e. in the background) and the `--rm` flag removes the container once it is stopped.
</Tip>


After running this command, verify that your local `prefect` profile is configured to point at your containerized server.

```bash
prefect config view --show-secrets
```

Open the dashboard in your browser:

```bash
prefect dashboard open
```

For more information, see the Docker topic about [Networking using the host network](https://docs.docker.com/network/network-tutorial-host/).

## Run as a non-root user

The image runs as root by default. To run as the built-in `prefect` user, use `--user 1001` (or `--user prefect`):

```bash
docker run --rm --user 1001 -p 4200:4200 \
  -e PREFECT_UI_STATIC_DIRECTORY=/tmp/prefect-ui \
  prefecthq/prefect:3-latest prefect server start --host 0.0.0.0
```

This user has primary group 0 and home `/home/prefect`, so the default Prefect home, `~/.prefect`, is writable.
Both `/home/prefect` and `/opt/prefect` are writable by group 0, including arbitrary user IDs in that group.
Root continues to use `/root/.prefect`.

Set `PREFECT_UI_STATIC_DIRECTORY` to a writable directory so the server can prepare both UI bundles. The server creates separate `v1` and `v2` subdirectories there instead of writing to the installed package directory.

For a read-only root filesystem, provide writable temporary storage with `--tmpfs /tmp` and set `PREFECT_HOME` to a directory there:

```bash
docker run --rm --user 1001 --read-only --tmpfs /tmp \
  -e PREFECT_HOME=/tmp/.prefect -p 4200:4200 \
  -e PREFECT_UI_STATIC_DIRECTORY=/tmp/prefect-ui \
  prefecthq/prefect:3-latest prefect server start --host 0.0.0.0
```

For an arbitrary UID without an `/etc/passwd` entry, `HOME` defaults to `/`. Set `PREFECT_HOME` explicitly to a writable directory even without `--read-only`:

```bash
docker run --rm --user 12345:0 --read-only --tmpfs /tmp \
  -e PREFECT_HOME=/tmp/.prefect -p 4200:4200 \
  -e PREFECT_UI_STATIC_DIRECTORY=/tmp/prefect-ui \
  prefecthq/prefect:3-latest prefect server start --host 0.0.0.0
```

Data in `/tmp` is ephemeral. To persist server data, mount a writable volume and set `PREFECT_HOME` to that location instead. Ensure the volume permissions allow your container user to write to it.
