Integrations to extend Prefect's functionality with Redis.

## Getting started

### Install `prefect-redis`

The following command will install a version of `prefect-redis` compatible with your installed version of `prefect`. 
If you don't already have `prefect` installed, it will install the newest version of `prefect` as well.

```bash
pip install "prefect[redis]"
```

Upgrade to the latest versions of `prefect` and `prefect-redis`:

```bash
pip install -U "prefect[redis]"
```

### Register newly installed block types

Register the block types in the `prefect-redis` module to make them available for use.

```bash
prefect block register -m prefect_redis
```

## Connection timeouts

`PREFECT_REDIS_MESSAGING_SOCKET_TIMEOUT` (default `60` seconds) and
`PREFECT_REDIS_MESSAGING_SOCKET_CONNECT_TIMEOUT` (default `10` seconds) bound
how long a Redis client waits on a read or connect before raising. Earlier
versions defaulted both to no timeout, so a dead connection during a Redis
outage could hang forever instead of failing and reconnecting. There's
currently no way to restore the old no-timeout behavior from an environment
variable; set `socket_timeout=None` when constructing `RedisMessagingSettings`
directly if you need it.

A consumer whose `PREFECT_REDIS_MESSAGING_CONSUMER_BLOCK` exceeds
`PREFECT_REDIS_MESSAGING_SOCKET_TIMEOUT` extends its own client's timeout
automatically, so a longer blocking read won't time out spuriously — no
manual coordination between the two settings is needed.
